**Версия:** 1.2 (Complete Architecture & Lifecycle)  
**Дата:** 30 июля 2026 г.  
**Профиль педагога:** Подготовка к школе & Репетитор начальных классов (1–4 классы)  
**Автор:** Product & Engineering Team  
**Статус:** Утверждён к разработке  

---

## 1. Обзор продукта

### 1.1 Описание
Продукт представляет собой единую цифровую платформу для педагога начального образования и дошкольной подготовки, состоящую из **публичного веб-сайта (Лендинга)** и **Telegram-бота (с Telegram WebApp)**.

Главная задача платформы — презентовать педагогический опыт, предоставить удобный **интерактивный календарь свободных слотов**, собрать полную информацию о ребёнке, выдать реквизиты для оплаты (СБП/карта), принять подтверждающий чек и дать педагогу **полный контроль над управлением заявками** (включая перенос времени и изменение данных клиентов) через Telegram и Админ-панель.

### 1.2 Цели продукта
- **Презентация и доверие**: Заботящийся, профессиональный бренд педагога начального образования и дошкольной подготовки.
- **Автоматизированное бронирование слотов**: Родитель видит только свободные часы педагога и самостоятельно выбирает удобное время.
- **Оплата по реквизитам с верификацией чека**: Простой механизм оплаты без комиссий эквайринга — клиент переводит по СБП/номеру карты и прикрепляет фото/скриншот/PDF чека.
- **Полное управление заявками для мамы (в 1 клик)**: Педагог получает в Telegram полное уведомление с возможностью не только подтвердить оплату, но и **отредактировать данные клиента, поменять дату/время или перенести занятие**.

### 2.1 Модули архитектуры

1. **Точки входа (Лендинг / Telegram-бот)**:
   - Публичный веб-сайт на Next.js с описанием услуг, отзывов и интерактивным календарем.
   - Telegram-бот с быстрым стартом через WebApp (TWA).

2. **Авторизация (Supabase Auth & Telegram WebApp Auth)**:
   - Безпарольный вход по номеру телефона / Telegram ID для клиентов.
   - Защищенный вход с правами администратора для мамы-педагога.

3. **Личный кабинет родителя**:
   - Список текущих и прошлых записей на уроки.
   - Статус подтверждения оплаты.
   - Ссылки на онлайн-комнату проведения уроков (Zoom / Яндекс Телемост).

4. **Админ-панель (для мамы-педагога)**:
   - Веб-интерфейс + Telegram WebApp для управления расписанием.
   - Создание/удаление свободных слотов.
   - Реестр всех заявок с фильтрами по статусам.
   - **Редактирование заявок**: перенос времени, изменение имени ребенка/родителя, изменение контактов и комментариев.

5. **API & База данных**:
   - REST/GraphQL API на базе Supabase PostgreSQL.
   - Защищенное хранилище `Supabase Storage` (бакет `receipts` для файлов чеков).

6. **Модуль Оплаты**:
   - Отображение карты/СБП реквизитов.
   - Загрузка файлов чеков (JPG, PNG, PDF).
   - Ручное верификационное подтверждение педагогом.

## 3. Путь от MVP до Тестирования (Жизненный цикл разработки)

Процесс разработки строится по итеративной циклической модели с постоянной обратной связью:

```
 💡 ИДЕЯ ──► 📦 MVP ──► 🎨 ПЕРВЫЙ ПРОТОТИП ──► 🛠️ ДОРАБОТКИ ──► ☁️ ИНТЕГРАЦИИ ──► 🛡️ БЕЗОПАСНОСТЬ ──► 🧪 ТЕСТИРОВАНИЕ
    ▲                                                                                                       │
    └───────────────────────────────── Итерационный цикл фидбэка ───────────────────────────────────────────┘
```

### Этапы жизненного цикла:
1. **Идея**: Сформирована концепция системы записи на онлайн-уроки с валидацией чеков и управлением из Telegram.
2. **MVP**: Разработка базового лендинга, интерактивного календаря слотов и формы отправки заявок.
3. **Первый прототип**: Рабочая версия на Vercel + Supabase с возможностью пройти путь от выбора слота до загрузки чека.
4. **Доработки**: Добавление функционала **редактирования заявок** мамой из Telegram и Админки (перенос даты/времени, изменение данных клиента).
5. **Интеграции**: Подключение Telegram Bot API, вебхуков Vercel, бакета Supabase Storage и вызова онлайн-комнат.
6. **Безопасность**: Настройка Row Level Security (RLS) в Supabase, защита персональных данных ФЗ-152, шифрование токенов.
7. **Тестирование**: Проведение нагрузочного и UX-тестирования на мобильных устройствах, проверка отправки чеков в PDF/JPG.

## 4. Сценарий работы и Интерактивное Управление в Telegram

### 4.1 Сценарий бронирования родителем (User Flow)
1. Родитель выбирает услугу (*Подготовка к школе* / *Репетитор 1-4 классов*).
2. Выбирает дату и свободный временной слот в календаре. Слот запечатывается на 15 минут.
3. Заполняет анкету: имя родителя, телефон, Telegram, имя и возраст ребенка, комментарий.
4. Видит реквизиты СБП/карты, делает перевод и прикрепляет файл чека (JPG, PNG, PDF).
5. Нажимает **«Отправить заявку»**.

### 4.2 Уведомление и Редактирование Заявки в Telegram Мамы

При поступлении заявки маме в Telegram приходит карточка со всеми данными и **интерактивным меню управления**:

```markdown
🔔 НОВАЯ ЗАПИСЬ НА УРОК! (Чек прикреплён)

📚 Услуга: Подготовка к школе (45 мин)
📅 Дата и время: 15 октября, 16:00
💰 Сумма: 1 500 ₽

👤 Родитель: Ольга Смирнова
📞 Телефон: +7 (916) 123-45-67 (@olga_smirnova)
👶 Ребёнок: Артём, 6 лет (Подготовка к 1 классу)

📝 Комментарий родителя:
«Плохо запоминает буквы, нужно развить чтение по слогам.»

🧾 Чек оплаты: [Прикреплённый документ/фото]
```

**Интерактивные кнопки под сообщением:**
- ✅ `[Подтвердить запись]` ➔ Слот становится `confirmed`, клиенту уходит подтверждение.
- ✏️ `[Изменить заявку]` ➔ Открывает меню редактирования:
  - 📅 **Поменять дату/время** (перенос слота на новое время).
  - 👤 **Изменить данные клиента** (исправить имя, телефон, возраст ребенка).
  - 📝 **Отредактировать комментарий**.
- ❌ `[Отклонить / Неверный чек]` ➔ Свободный слот возвращается в календарь.
- 💬 `[Написать родителю]` ➔ Прямая ссылка на диалог.

## 5. Концептуальная модель данных (Supabase PostgreSQL)

```sql
CREATE TYPE booking_status AS ENUM ('pending_payment', 'receipt_uploaded', 'confirmed', 'rescheduled', 'cancelled');
CREATE TYPE grade_level AS ENUM ('preschool_5', 'preschool_6', 'grade_1', 'grade_2', 'grade_3', 'grade_4');

-- Таблица слотов расписания
CREATE TABLE time_slots (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    start_time TIMESTAMP WITH TIME ZONE NOT NULL,
    end_time TIMESTAMP WITH TIME ZONE NOT NULL,
    is_booked BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Таблица заявок
CREATE TABLE bookings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    slot_id UUID REFERENCES time_slots(id) ON DELETE RESTRICT,
    service_title VARCHAR(255) NOT NULL,
    price DECIMAL(10, 2) NOT NULL,
    
    -- Данные родителя и ребенка
    parent_name VARCHAR(255) NOT NULL,
    phone VARCHAR(50) NOT NULL,
    telegram_handle VARCHAR(100),
    child_name VARCHAR(255) NOT NULL,
    child_grade grade_level NOT NULL,
    comment TEXT,
    
    -- Оплата, чек и история изменений
    receipt_file_url TEXT,
    status booking_status DEFAULT 'pending_payment',
    admin_notes TEXT, -- Заметки педагога
    rescheduled_from_slot_id UUID, -- Для истории переносов
    
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

## 6. Инструкция по безопасности и привязке аккаунтов (Vercel & Supabase)

1. **Vercel Access Token**: Передается разработчику для деплоя фронтенда. Отозвать можно в 1 клик в *Account Settings ➔ Access Tokens ➔ Revoke*.
2. **Supabase Project Keys**: Разработчик получает `Project URL` и `Anon Key`. В любой момент доступы можно сбросить через *Project Settings ➔ API ➔ Reset API Keys*.
3. **Безопасность данных детей (ФЗ-152)**: Все файлы чеков хранятся в защищенном бакете Supabase Storage со скрытыми URL-адресами, доступными только через авторизованную сессию админа.
